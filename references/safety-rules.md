# Safety Rules

按风险等级说明操作。不要为同一目的的每条低风险读取命令重复打断用户。

## 低风险：批量说明后执行

例如列目录、读文件、搜索文本、查看 Git 状态、运行不写数据的检查。一次说明这一组命令的目的、范围和成功标志即可。

## 中风险：说明实际影响后执行

例如修改项目文件、安装常规依赖、生成构建目录、创建本地 commit。说明会改什么、可能产生什么文件、如何判断成功。正常且已在用户任务范围内的实现步骤不需要额外反复确认。

## 高风险或外部操作：取得明确授权

- 删除或覆盖用户文件。
- `git reset --hard`、`git clean -fd`、强制推送。
- 访问外部账号、创建远程仓库、push、部署或公开发布。
- 可能收费的 API、云资源或生产数据库操作。
- 修改生产配置、真实用户数据或凭据。

## 文件和 Git

- 保留用户已有改动，不回滚无关内容。
- 大改前建议 checkpoint，或至少记录 `git status` 和 `git diff --stat`。
- 不删除未跟踪文件，不隐藏测试失败。
- push 前检查 `.env`、密钥、token、session、证书和用户数据。

## GitHub

- PRD 确认不等于 GitHub 授权。
- 先确认是否同步，再确认 public/private。
- 不重复创建仓库，不切换未知账号或组织。

## 失败

报告失败步骤、错误摘要、可能原因、已尝试内容和建议下一步。不要静默重试高风险操作，也不要假装成功。
